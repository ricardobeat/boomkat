Method: one serial sample per binary per unchanged mini input, alternating
binary order between benchmarks. No warmup, no repeated rounds, no profiling.
Fresh release builds using just build boomkat, same toolchain/settings/machine.
Embedded Date.now timers exclude initial parse/setup/teardown, but include
dynamic compilation inside timed benchmark calls. Whole-process wall/CPU/RSS
and component timers are retained in results.json. These are single samples,
not statistical confidence intervals. No speed attribution to individual passes.

The candidate includes ALL six flat-AST/runtime optimization families: the
three prior constant-analysis passes plus the three new runtime patterns.
Main already has threaded typed-array load/store paths. Rebase adaptation
shares main's typed-array base, numeric load and integer store primitives.
The previous old-baseline gains are superseded for evaluating current main.

Main improved significantly since the original baseline. Against main, Zlib
and Mandreel regress, and Mandreel peak RSS rises by about 12.8 MiB. The latter
is process peak memory, not an isolated allocation attribution. This experiment
does not separate the old fact columns from the new compact kinds/pair handlers.
Do not merge/enable this branch on the basis of the earlier speed result.

Minimal validation only: focused release script/module regression, focused
debug unoptimized script/module regression, canonical bytecode inspection for
all eight paired variants, and diff whitespace check. Test262 was not run.
No broad correctness claim; detached/resizable/immutable buffer guards are
present, but comprehensive conformance/fault-injection coverage is deferred.

Prototype scope: compact expression kinds and redundant Int32 |0 removal;
fastint add/subtract + |0; fastint bit masks + strict zero branches; immediately
adjacent signed/unsigned immediate shift + numeric typed-array load/store.
No postincrement fusion or flow-sensitive propagation through mutable locals.
The paired opcodes keep original consumers and publish intermediate results
so switch/partial fallback does not replay operations. Eight new opcodes bring
LAST_OP to 254 on this revision; opcode-space pressure needs attention before
any production expansion.

Reproduce: build the two recorded revisions with the same release settings,
copy main to bin/before and candidate to bin/after, and run this directory's
run.py. Binaries are locally retained and ignored; hashes and source/build
provenance are in results.json and provenance.json. No main checkout edits.
