## Session 303 (2026-07-31)

**49,775 pass / 35 fail / 4 CE → 49,814 pass / 0 fail / 0 CE. Every phase 0-25 reports zero failures and zero unexpected compile errors.**

Note on the session-300 entry below: it records "0 fail / 0 CE" at 45,617 pass. That was measuring a smaller universe — the ~4,600 `$DONOTEVALUATE` parse-negative tests were still skipped wholesale. Un-skipping them (`scripts/run_test262.py:851` now compiles `phase: parse` negatives and scores rejection as a pass) is what surfaced the 35 failures cleared here. Not a regression.

- **Async-generator drain wedged permanently after any rejecting `throw()`** (plan 063, 3466a2aa) — every subsequent next/return/throw returned a forever-pending promise. Root cause: `ag_current_request` was one field serving two roles with incompatible lifetimes — GC root (must survive *through* the settle, which allocates) and re-entrancy guard (must be released *before* the settle, which triggers reactions synchronously). Correct in 4 places, missing in 4. Split into `ag_root_promise` + `ag_body_in_flight`, both lifetimes moved into the two settle helpers all 9 sites already funnel through. Also repaired a latent GC hazard the old body-resume path carried: it cleared the root then held the promise in an unrooted local across an allocating settle. test262 covered only 2 of the 4 broken shapes.
- **Class-body early errors** (plan 062, 5 commits) — 27 phase-15 failures. Sub-cluster `static # x` was not a class-body bug at all: `match_static_block_prefix` caught a lookahead `LEX_ERROR` and returned false, so parsing resumed mid-token. The agent introduced and self-caught a regression in phases 5/6 (a new duplicate-lexical check tripped over `pre_scan_lexical_decls` resetting `prev_tt` after declarator lists ending at `=`, so `let A = class A {}` collected `A` twice) — harmless while the spans drove idempotent emission, fatal for a validator. **If anyone wires another rejecting check onto that pre-scan, this is the trap.**
- **`await`/`yield` reserved per the inherited `[?Await]`/`[?Yield]` params** (plan 064, 8d28b8a0) — 6 failures, but the real surface was far wider: bare `yield` was accepted as an IdentifierReference in *every* async function body, because async functions set `is_generator` for the coroutine machinery. `await_is_identifier` already existed as the shared predicate and three sites had re-implemented it with differing conditions; the fix *removes* two copies.
- **`typeof arguments` returned `"undefined"`** (plan 065, b6fa8af7) — silent wrong value in idiomatic code, no test262 coverage. Only `primary_expr` sets `uses_arguments`; the two bare-identifier fast paths under `TYPEOF` returned before reaching it, so the function compiled with no arguments object and `TYPEOFIDENT`'s not-found branch answered. Any *second* mention of `arguments` masked it. Four hand-rolled copies of the predicate collapsed into one helper; golden bytecode unchanged (compiler flag only, no emission change).
- **Escaped keywords in IdentifierName positions** (plan 066, 615b6afd) — the last 4 test262 issues, all over-rejection. Reported as 2 shapes; turned out to be **9 sites with one root cause** — a lookahead that must *consume* a token to decide what it is applies `advance`'s escape gate before the branch that would exempt it. The 7 unreported ones have no test262 coverage.
- **Structured console output** (`e234d4df`, 5 commits) — `src/builtins/inspect.c3`, a standalone 1106-line renderer behind `inspect_root`/`inspect_nested`. `console.log({a:1})` printed `[object Object]`; now matches captured reference output byte-for-byte across plain objects, arrays, holes, Map/Set, functions/classes, errors, boxed primitives, null-prototype objects, TypedArrays, symbols, BigInt, `-0`, `[Circular *1]`, the depth-2 limit, and line-breaking/column-grouping. Remaining deviation: `%o` does not imply `showHidden`/depth-4.
- Gates: full suite 49,814/0/0, golden 28/28, rosetta 41/41, test-local 299 scripts + all sub-suites, console-format 5796 lines.

- **`await` as an arrow parameter** (`8b05e9f9`) — `await => 1`, `(await) => 1`, `(a, await) => a` and `(...await) => …` were rejected. ArrowParameters inherit the *enclosing* `[Await]`, so the reservation is read off the enclosing context rather than the arrow's own flag. The head scan tested for `TokenType.IDENTIFIER` directly, which no `await` token ever is, so the head never registered as an arrow at all: a detection gap, not an over-broad reservation. Folded in the last hand-rolled copy of `await_is_identifier`, closing the design-debt item.
- **A GC lifetime bug that no gate could see** (`6722c1a6`) — `test/test_async_loops.js` segfaulted under collection pressure. Not a value the mark phase missed, but the inverse: a generator/async resume restores `gs.saved_regs` through `tval_copy_ref`, taking a reference per heap value, while bypassing `track_heap_store` with `max_heap_reg` freshly zeroed. `decref_callee_regs` sweeps only `[0..max_heap_reg]`, so higher restored registers were neither released nor cleared, and `vm_mark_activations` (which over-scans past `num_regs`) later read those stale pointer bits through a different frame at a different bottom. `track_restored_regs` raises the watermark over the restored window at both resume sites. **`just test-gc-stress`** now builds with a `GC_STRESS` feature flag that pins the collector trigger, plus ASAN; the default path is byte-identical. It runs 20-30 minutes, so it suits a nightly rather than a per-commit gate. Verified non-vacuous: neutralizing the two call sites makes ASAN abort on poisoned memory.

**Repo-wide hazard found in passing:** `StrBuf.data` points into its own `inline_buf`, so copying the struct **by value** dangles the pointer — but only while un-grown, which is why it failed on `[1..10]` and worked on >256-byte entries. Any other site that copies a `StrBuf` by value has the same latent bug.

Plans 064, 065, and 066 each fixed it by *removing* copies rather than adding one. One known copy remains, tracked in BACKLOG under Design debt.

## Session 299 (2026-07-24)

Nine-agent fleet over the remaining backlog. **41,781 → 41,830 pass, 2 → 0 fail.** Three agents' framings turned out to be wrong in instructive ways.

- **Large-string registry backstop** (faa59dd2 + 37252db2) — `HString.registry_slot` reuses the dead `next` field (header stays 24B); Heap holds a swap-with-last array of >256B strings, swept in phase 3b under `string_sweep_safe`, drained in reset()/destroy(). With a collector that can find these strings, the bb6c01e hot-path decrefs came back out: function_call 335→318ms, loop 278→233, recursion 284→239, arithmetic 641→517. Leaks hold at 15/880B; 100k abandoned large strings peak at 13.7MB RSS. The agent's own near-miss is worth recording: it first stored the slot in `hash`, which `equals_hstring` uses as a fast-reject *specifically* for non-interned strings — silently breaking `===` on large strings until phase 0 caught it.
- **The decref revert fixed a real crash** (37252db2) — the last full-suite failure, `FinalizationRegistry/.../unregister-symbol-token.js`, segfaulted deterministically on main and *predated* the whole session (reproduced on e53cb15). Bisecting the day's commits put the fix squarely on the decref revert: `resolve_call_var`/`resolve_call_global` had been releasing the callee register while it was still the borrowed callee slot in flight for the fused CALL path. So bb6c01e's "owned-register discipline" was too strong a claim — that slot is a borrow — and what read as a 3-7% perf tax was also a latent use-after-free.
- **GC temproots vs. native frames** (e87df06f) — `mark_and_sweep(safepoint)` cleared every temproot because "at a safepoint nothing is in flight." False whenever a builtin allocates a result and re-enters the VM holding it only in a raw C3 local: `Array.prototype.map`'s result array was swept mid-loop and the next write hit a recycled header. Fixed with a `native_frame_depth` counter at the `dispatch_builtin` chokepoint. Verified by bisection under an aggressive all-sizes GC trigger — both target tests fail without it, pass 3/3 with it. Not map-specific and not batch-only, contrary to the original repro recipe.
- **Spec fixes** — accessor frames never assigned `new_target`, so a getter reached via `super.x` inherited the enclosing constructor's (107fe880). Strict `delete ta[i]` computed the failure but never threw, and missed string keys entirely (82546d30, +8). `includes()` short-circuited on detach instead of matching undefined, and `[[Set]]` skipped ToNumber on non-arridx canonical indices (0d5c8697, +4). Global function declarations shared DECLVAR with `var`, so redeclaring over a non-configurable global flipped `configurable` back to true — new DECLGLOBALFUNC opcode, kept off the VarIC (06aee563, phase 7 +6).
- **The toString "escape" bug was a stale borrow** (ee740c2d) — `hoist_decls` captured the decl name as a borrow into the lexer's shared `ident_buf`, which `compile_inner_function` then overwrote by re-lexing the body. A top-level `function a(bcd){...}` created a global named after the last identifier scanned *inside* the body. Interning the name at capture fixes it. The escaped name is still decoded in toString output; the test only passes because its harness accepts either form, so verbatim-name preservation is still unimplemented and untested.
- **Skip-list re-tier needed correction** (1784700b + 57ccfad7) — the agent reported an empty token diff while actually adding five tokens, two of them (`Atomics.pause`, `regexp-duplicate-named-groups`) for features we implemented and ship passing. Its `logical-assignment` → `logical-assignment-operators` "typo fix" would have started skipping 8 passing tests; logical assignment is implemented, so the dead misspelling was load-bearing and the token is now gone. Verified by a machine-checked token-set diff against pre-re-tier main.
- **Escaped identifiers corrupted declaration names** (7d9cba20) — the lexer decodes escaped identifiers into one shared `ident_buf` and returns a borrow; declaration sites stored that borrow into `scope_stack`, class `methods[]`, and module tables, so any later identifier scan in the same function/class/module silently corrupted the earlier name. `function f(\u{62}, \u{63}){ return b + c; }` threw `'b' is not defined` (qjs: 3). Fixed by interning at capture across params, declarators, loop heads, function/class names, method names, and every import/export form. Wider than the repro: class methods and module imports were broken too, both confirmed pre-fix and now matching qjs.
- **Bare-`var` inline-cache clobber, and the regression fixing it caused** (8654b5f → 3ea265c) — `DECLVAR`'s VarIC wrote unconditionally, so a hoist stub in a loop body overwrote a live global with undefined on the second iteration (`var x=5; for(...){var x;}` gave undefined; qjs 5). Pre-existing. The first fix tested the runtime value for undefined, which broke `for (var v of [1,2,3,,5])` — a hole legitimately declares undefined and must store it (phase 14 −3, caught by the full suite). Corrected with a `DECLVAR_HOIST` opcode: the initializer-less case is static, not a property of the value. An investigating agent had declared this unreachable; its env-pooling analysis was right but its "never inside a loop" premise was not.
- Gates: full suite 41,830/0/0, golden 10/10, rosetta 100/100, benches at or better than baseline.
- **The "batch-runner" leak was a public-API leak** (75bf5ce5 + 0dd5f03) — first the agent's find: Symbols belonged to no owning list at all, and ~39 sites inserted into the string table without taking ownership. Real, but measured at only 33.54 → 32.37 KB/cycle. The agent said plainly it had not fixed the headline number, which is what made the rest findable. Asking whether the leak was runner-only broke it open: single-shot runs and compile-once scripts are clean, but *compiling a function at runtime* leaked every time — `new Function("a","return a;")` × 1000 gave 1000 leaks/48 KB on the plain public API, `eval` of a function/class scaled with nesting, and `eval("var x=1;")` leaked nothing. Cause: `CompiledFunction.name_ptr`/`.src_ptr` are copies taken out of the compiler's scratch buffers to outlive the compile, and `free_compiled_funcs` never released them. All five shapes now 0; worker growth **33.54 → 0.19 KB/cycle**, flat at 6.5 MB. Two framings had to be discarded first — the previous agent's "large strings" and my own "reset() misses a subsystem" — and neither was where the memory went.
