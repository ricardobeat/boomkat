# Engine scope

What this engine implements, what it does not, and why. For the test262 numbers
themselves see `test262_results/latest.json`; for how those compare against
other engines see `test262-comparison.md`; for what the suite actually skips
see `SKIP_DIRS` / `SKIP_FILES` / `UNSUPPORTED_PATTERN` in
`scripts/run_test262.py`, which carry their reasoning inline and are the
authority.

## What it is

An ES5/ES6 engine meant to be embedded. A host links it and supplies
its own runtime surface: module loading, timers, I/O, and whatever globals that
host wants. The engine's own target is ECMA-262, not any particular runtime's
API.

Both execution modes. Strictness is per function: scripts, ordinary function
bodies and dynamic `Function()` bodies default to sloppy, modules and class
code are strict, and a `"use strict"` prologue raises a unit to strict
(`plans/083-sloppy-mode.md`).

## In scope, and implemented

The ES5/ES6 core, plus the later additions that ordinary code now assumes:

- Objects, prototypes, property descriptors, accessors, `Reflect`, `Proxy`
- Classes, private fields and methods, static blocks
- Destructuring, spread, default and rest parameters, template literals
- `let`/`const`, block scoping, TDZ
- Iterators, generators, `for-of`, async functions, async generators, `for await`
- `Promise`, the microtask queue, `Map`/`Set`/`WeakMap`/`WeakSet`
- `WeakRef` and `FinalizationRegistry`
- `Symbol`, including the well-known symbols
- **Cross-realm behavior.** Realms share a heap and have independent globals
  and intrinsics. The C API exposes `bk_new_context(runtime)`; test262 uses
  `$262.createRealm`. Realm storage lives until the runtime closes.
- TypedArrays, `ArrayBuffer` (including resizable and immutable), `DataView`
- `Atomics` and `SharedArrayBuffer`, shared between agents: threads that each
  run their own runtime
- ESM: `import`, `export`, namespace objects, dynamic `import()`, import
  attributes (`with { type: "json" | "text" | "bytes" }`)
- Iterator helpers (`Iterator.prototype.map`/`filter`/`take`/`drop`/...)
- Proper tail calls (ES2015 §14.8): a call in syntactic tail position reuses
  the caller's frame, so tail recursion runs in constant stack
- `BigInt`, arbitrary precision (a 32-bit limb vector; the only ceiling is
  `BIGINT_MAX_LIMBS`, ~2 billion bits, which turns a runaway expression into a
  RangeError instead of exhausting memory)

## Optional features and scope exclusions

- **The rest of Annex B**, beyond the parts sloppy mode needs. Annex B.3.1
  (duplicate parameters, mapped `arguments`, `delete x`), B.3.2 labelled
  function declarations, B.3.3 for function declarations in a block, B.3.4
  function declarations as `if` bodies, B.3.5 initializers in for-in heads,
  B.3.9 runtime errors for function call assignment targets, legacy octals and
  octal escapes are in. So are `Date.prototype.getYear`/`setYear` and
  `toGMTString` (B.2.4/B.2.6). Absent: the
  `String.prototype` HTML methods, the `RegExp` legacy statics, and the legacy
  eval-code and global-code var-hoisting rules.
- **ECMA-402.** The small Intl profile supplies English NumberFormat, PluralRules,
  DateTimeFormat, RelativeTimeFormat, ListFormat, DurationFormat and DisplayNames.
  DateTimeFormat resolves all sixteen calendars supported by Temporal, including
  their eras and leap months. Number/BigInt, Date, Array and TypedArray locale
  methods call the internal services. DateTimeFormat and NumberFormat support
  the optional legacy constructor chaining behavior.
  `Intl.Segmenter` implements Unicode 17 default grapheme, word and sentence
  boundaries; dictionary word segmentation is outside this profile.
  `Intl.getCanonicalLocales` and `Intl.Locale` validate and canonicalize locale
  identifiers with CLDR aliases and likely subtags. Locale region queries read
  CLDR preferences, week data, hour cycles, numbering systems and IANA zones.
  Decimal numbering systems with ten digit code points are available through
  the numberingSystem option and Unicode locale keyword.
  The positive `INTL` feature enables these services with English formatting.
  `INTL_FULL` adds the locale rows generated by `scripts/generate_intl_locales.py`.
  `INTL_COLLATOR` independently enables Collator; small builds use root data and
  full builds add ICU-derived locale tailorings and collation types.
  `just build boomkat --intl=none|small|full` selects the data profile.
  Size-focused builds default to `intl=none`, with Temporal and Collator disabled.
  `just build boomkat --intl=small --collator=true` enables root collation.
  Full builds enable Collator by default; `--collator=false` omits it.
  The full release CLI is `boomkat-full-icu`, with bundled native data, Collator,
  and Temporal enabled. The test runner detects Intl, Temporal, locale and Collator
  availability from the selected worker.
  Omitting INTL removes Intl. `-D NO_INTL_DATE` trims DateTimeFormat and
  `-D NO_INTL_NAMES` trims DisplayNames; boomkat_slim uses both. Date locale methods
  use the fixed English renderer when DateTimeFormat is absent; Number/BigInt
  locale methods return ordinary strings when Intl is absent. SLIM retains source
  execution; TINY executes bytecode emitted by `boomkat_tiny_compile`. Both
  disable Intl and Temporal by default. See
  [architecture](architecture.md#tiny-bytecode-tools) for image compatibility.
- **Stage 3 proposals.** In scope, and implemented as test262 stabilizes them.
  Explicit resource management is in: the `using` and `await using`
  declarations, DisposableStack, AsyncDisposableStack, SuppressedError, and the
  @@dispose and @@asyncDispose symbols. Decorators and ShadowRealm are not
  implemented yet; their test262 files are skipped until they land.
- **Temporal.** The positive `TEMPORAL` feature exposes the namespace. It defaults
  to false for boomkat and true for boomkat-full-icu and conformance targets.
  PlainDate, PlainDateTime, PlainYearMonth, PlainMonthDay and
  ZonedDateTime resolve calendar fields and arithmetic through the same sixteen
  calendars as DateTimeFormat. Duration arithmetic uses the calendar of relativeTo
  and resolves zoned date units across IANA offset transitions. Time zones retain
  their complete historical transitions and recurring future rules. Temporal
  locale formatting calls Intl internally; ZonedDateTime uses its own time zone.
- **Multiple agents.** An agent is a thread running its own runtime, and the
  only thing agents share is a `SharedArrayBuffer`'s data block. `Atomics.wait`
  blocks, `Atomics.notify` wakes waiters in other agents, and `Atomics.waitAsync`
  promises settle (and time out) through the host's event loop, which the CLI
  and the test262 runner run. test262 drives the second agent through
  `$262.agent`, which the CLI and runner install. The C embedding API does not
  yet hand a buffer from one runtime to another. `CanBlockIsFalse` tests run
  with the main agent unable to suspend.

## Two notes for anyone editing the skip list

A skip is a claim that behavior is out of scope. It is not a place to park a
bug: an in-scope test that fails is a real bug, not a `SKIP_FILES` entry.

When you implement something, remove its skip in the same change.
