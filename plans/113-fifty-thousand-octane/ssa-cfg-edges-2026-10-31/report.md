# SSA predecessor edges and cyclic dominance

The SSA block splitter used zero, the entry-block index, for missing successors. Every one-successor or fallthrough block therefore appeared to have an extra edge to entry. Entry is special-cased during current graph construction and dominance, hiding the false edges semantically, but the four-predecessor limit could reject graphs with several such blocks. Use the existing SSA_BLOCKS sentinel for absent successors. The existing single-loop latch still explicitly names its real backedge.

A five-diamond JavaScript leaf has 16 bytecodes and 11 basic blocks. The control rejects SSA at graph construction; the candidate emits an inlined SSA leaf. With normal JIT warmup, diagnostic counters report 4,938 native leaf calls and completions; control reports graph rejection. The 912-byte ARM64 leaf contains branch tests and overflow-checked integer adds, but also spills and reloads join values across the diamonds. The source bytecode, emitted native disassembly, and control/candidate diagnostics are retained here. Seven alternating uninstrumented focused pairs run 914→777 ms median (-15.0%); this establishes a focused consumer, not a full-Octane result. The fixture covers all 32 boolean combinations, coercion recovery and callee mutation in interpreter, normal JIT and stress modes.

For the later cyclic graph work, dominators now converge on non-topologically ordered and cyclic graphs and exclude unreachable predecessors. Forward graphs retain a single pass. A separate path-exclusion oracle checks every one of 65,536 directed four-node graphs, including unreachable nodes, irreducible cycles, self loops and multiple backedges. Tests also exercise the actual block splitter, real loop latch predecessor, formerly rejected 11-block graph, and a dominance consumer in CSE. This does not admit cyclic function SSA: builder joins, backedge liveness, effect ordering, recovery and polls still require work. In particular, the allocator's flat definition-order intervals and its optimization of memory loads cannot safely be generalized to arbitrary cycles without accounting for backedge liveness and intervening effects.
