# Shared widened-bytecode decoding, 2026-10-31

Rat `9966cd7f` is a bounded infrastructure slice towards plan 113's indexed bytecode view; it is not a new optimizing tier and does not establish a throughput gain. `DecodedBytecode` returns a decoded instruction with its original boundary PC, opcode payload PC, next PC, and validity. Its caller must supply an instruction boundary. It rejects out-of-range and truncated or nested WIDE prefixes. The loop-alias operand analysis now uses this view and retains its conservative refusal of unmodeled register windows and immediates. The interpreter's existing WIDE expansion uses the same field-setting macro. Constant-pool operands continue to be distinguished from registers by the compiler's existing role table. This change does not claim general CFG edges, full operand-window decoding, SSA, or recovery snapshots.

The actual dynamically evaluated zlib `a1` bytecode in `../capture-dispatch-2026-10-31/a1-region-31045-bytecode.txt` motivated retaining both the WIDE prefix PC and its payload PC: it starts with r484 and has typed property operations after widened branches. The actual `test/test_sljit_highreg_loop.js` alias consumer produces a `hotAlias` function plan of 23,492 bytes and completes 366,592 loop-tier native iterations in both builds; the release report does not provide the loop body size. One unrelated reference function differs by four or eight generated bytes across builds. Logs are retained here.

An initial shared helper returned a temporary aggregate. ARM64 disassembly showed that this introduced a stack store on every WIDE switch dispatch and grew `vm_dispatch` from 62,364 to 63,152 bytes. Five mini pairs had zlib 3719→3740 ms, Mandreel 553→565 ms, TypeScript 1219→1234 ms. This form was removed. A field-setting macro plus a macro for the boundary view removes the extra emitted standalone helper and the temporary: the final ARM64 WIDE path is byte-for-byte identical at the same addresses, and `vm_dispatch` is again 62,364 bytes. The before/after instructions are retained here. The final macro evaluates its pointer, size and PC arguments once; a post-increment PC test enforces this.

The preceding macro build's five-pair mini medians were zlib 3721→3726 ms, Gameboy 275→275, Mandreel 553→554, TypeScript 1220→1223, Crypto 164→163, DeltaBlue 88→89. This is a neutral screening result, not an Octane score or speedup claim. The exact final side-effect-safe build gave zlib 3727→3743 ms in five pairs (one 4129 ms candidate outlier), Gameboy 275→274, and TypeScript 1221→1222. A seven-pair reversed-order zlib confirmation was 3713→3727 ms (+0.38%). The complete threaded WIDE handler is also byte-for-byte identical at the same address and size (752 bytes); this small observed timing difference has not been attributed to a dispatch change. The operand-analysis function grows from 328 to 344 bytes. No full Octane run was made for this infrastructure-only change. Direct decoder tests cover narrow and widened fields, PC boundaries, combined BC bits, invalid prefixes, argument evaluation, and a widened GETVAR whose constant index must not become register uses. ARM64 ASan and x86-64 embedding tests pass; the actual high-register fixture and local/Rosetta/modules interpreter-versus-JIT differential checks match. The default local build omits Intl and Temporal, so both modes have the same pre-existing nonzero local-suite status.

The next work is to build control-flow edges and recovery-aware operand uses over this view and then integrate it with shared cyclic SSA; returning a decoded instruction alone does not implement those capabilities. Full Octane remains far below 50K.
