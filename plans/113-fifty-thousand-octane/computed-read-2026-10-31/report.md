# Computed read continuation experiment — rejected

On rat `34f224e0`, a guarded prototype returned from the existing no-effect named-read helper for warmed non-index computed string/symbol reads, while declining proxies, accessors, coercing and non-interned keys before side effects. Only observed non-index sites received an extra join and stub. The patch and fixture are retained here; the implementation was removed from rat.

The focused `readLoop` bytecode is included. Its hot loop has `GETPROP r5 = r0, r1` at PC 3 followed by ADD, BORI and a backward branch. With an initial `alpha` key and subsequent `beta` key, the control exited at GETPROP 208 times, retired the compiled plan and executed 40,000,632 threaded instructions. The prototype remained compiled and logged 10,000,000 read-helper completions. A JIT-enabled embedding check also verified the helper counter increases. Interpreter, JIT and stress fixture checks and 55 focused comparisons passed; this was not a full release gate.

Matching diagnostic builds captured the actual emitted ARM64 assembly (`bk-control-native.asm` and `bk-cand-native.asm`); sizes were 5976 and 5988 bytes respectively. The added continuation is on the cold guard-failure path, with the hot fast property path retaining the same structure. Addresses and diagnostic counters differ between processes; these instrumented code sizes are not release measurements. In uninstrumented builds the focused workload had a 132→123 ms median across five alternating pairs, not a full-suite result.

Opcode-attributed `SLJIT_STATS` on seven real mini workloads found computed-read continuation sites only in PdfJS (seven sites, 436 helper hits) and TypeScript (two sites, four hits); no hits appeared in DeltaBlue, Richards, Gameboy, Mandreel or zlib. These counts increment on helper attempts and are an upper bound on useful completions. The five-pair mini screen was noisy: Mandreel control 715/1167/1190/1167/649 ms and candidate 709/825/1036/1058/649 ms; no reliable gain can be inferred. Since this path has essentially no hot production consumer in the measured workload, the implementation was rejected instead of adding code and maintenance for a synthetic win. The experiment does not establish whether more general effectful property continuations would be useful.
