# Plan 113: bounded dependencies for a pure SSA consumer (read-only analysis)

Finding: neither `Heap.prototype_epoch` nor shape generation is a value-write dependency. They must not alone justify folding a mutable property value or method. `HObject.put_prop` replaces an existing value through `Heap.store_slot` and only `set_prop_flags` bumps the prototype epoch when flags actually change (src/hobject.c3:2165,1825; src/heap.c3:3770). The threaded own-data fast paths assign the slot directly for primitives (src/vm/vm_execute_threaded.c3:2964,3003); native `FunctionEmitter.slot_store` emits a direct store (src/vm/vm_sljit_property.c3:57). `Heap.store_slot_ref` likewise has no epoch bump. This also applies when the owner has `prototype_observed`; the existing epoch is designed to protect lookup/layout, not the value. A function-valued property can be replaced without a shape change. The warning at src/vm/vm_control.c3:994 already describes precisely this issue.

Existing layout/lookup dependencies: shape id plus per-shape generation / heap shape-recycle epoch handles shape recycling; the shared epoch is incremented at shape reclamation and when an IC-bound object's layout moves. `VarICEntry.slot_ptr` is valid only under its recycle epoch (src/hobject.c3:4117), and `Heap.invalidate_var_ic_entries` advances it on environment changes (src/heap.c3:4667; src/env.c3:609,663). For inherited ordinary named reads, cache population marks each prototype observed (src/vm/vm_property.c3:116-160); additions, descriptor changes, layout movement, deletion/free, and setPrototypeOf advance prototype_epoch when the affected object was observed (src/hobject.c3:388,1825,2225,2903,3843; src/heap.c3:3888). Receiver own-shape, ordinary class, first-prototype identity and the cache epoch must still be checked; a shape does not determine its prototype. Check exact paths and all links/owners before extending this beyond existing `ic_epoch_live` rules. `prototype_epoch` is global and 64-bit; shape recycle epoch is 32-bit; overflow behavior should be handled as existing code does, not silently assumed impossible.

A bounded first consumer can avoid any new mutation hooks or code-retirement changes by validating the *live values once per entry*, then substituting an observed primitive into a strictly effect-free SSA interval. Existing `ssa_binding_mask` / `SsaEmitter.binding_entry` already do this for numeric global bindings: validate live VarIC epoch, accessor flag and non-null slot, compare the slot bits with the observed primitive, then `ssa_build` substitutes CONST_I/F (src/vm/vm_sljit_ssa_leaf.c3:30-40,95-126; src/vm/vm_sljit_ssa_build.c3:189-206). Extend the same idea for `GETGLOBAL; GETPROPC` when feedback establishes an ordinary receiver and own data numeric/boolean property: validate the binding using the existing realm/slot validity rules, take the *live object pointer* from the global slot, check object tag/non-null/class, shape id and shape generation/recycle epoch, resolve current inline vs allocated storage, and compare that live property's boxed bits to the observed immediate before emitting the constant. Never dereference an embedded, unrooted object address. If factoring out the object slot, it must remain rooted by the live binding or be explicitly traced for the full dependency lifetime, including GC and IC retirement. Restrict inputs to exact primitive bit patterns (including signed zero/NaN handling) and actual non-accessor, non-exotic, non-dictionary layouts; do not encode refcounted strings as unrooted pointers.

All guards must dominate the substituted uses and happen before externally observable effects. Limit initial admission to the existing pure/one-terminal-write leaf rules with no callbacks, allocations, GC polls, re-entry or unknown JS calls between the validation and last use. The terminal write must not precede any dependent use, and any potential aliasing store invalidates the fact. A failure before the first effect resumes the untouched baseline frame, as existing SSA leaves do. This is a reusable per-entry guarded specialization, not an epoch-only constant or a watchpoint. It still loads and compares one slot per entry; it removes repeated read/boxing and permits constant propagation within that interval, but does not satisfy plan 113's stronger goal of *no runtime global/property resolution*. The actual execute-like consumer must be traced and measured before broadening.

For method inlining, existing `ssa_inline_call` emits `CHECKFN` on the *live resolved method*, verifying object tag, callable/function/non-bound/non-proxy class, compiled-function identity and realm (src/vm/vm_sljit_ssa_inline.c3:55-74; src/vm/vm_sljit_ssa_emit.c3:627-658). Keep that guard or prove an equivalent live target check once per effect-free interval. Prototype layout + epoch cannot establish method value. `CompiledFunction*` is a code identity, not enough on its own to establish receiver/function realm; the guard checks both. Do not embed a weak owner or function object pointer without explicit rooting and retirement protection. For multiple reads, reuse already-guarded values/facts under dominance only; a live `CHECKFN` and property slot comparison can be shared only where no aliasing store or re-entry intervenes.

If the stronger goal requires *eliminating* the entry slot/value compare, a new value-write dependency is unavoidable for writable or internally mutable values. A selective observed-owner/value flag and heap value epoch (or precise watcher/list) must be checked by all of: generic existing-slot writes `HObject.put_prop` and `Heap.store_slot[_ref]`; threaded primitive `th_put_cached` / `th_put_lookup` and env-slot writes; native `slot_store`, SSA terminal stores, and generated absent append paths as applicable; define/delete/descriptor updates; environment declaration/rebinding/invalidation; prototype replacement; builtin raw/internal writes, C API `bk_set_property`, `bk_set_global_property`, `bk_delete_property`, `bk_set_function` and GC/free/shape reuse. Audit all direct `PropValue` writes and host hooks rather than assuming every store passes Heap.store_slot (the threaded and emitted examples prove it does not). Either guards on observed writes must bail to a central hook, or every generated and threaded direct store must bump/invalidate. Invalidation must prevent re-entry through linked native entry points, preserve active code until no activation can execute it, and force recovery after any helper/JS mutation before subsequent dependent operations; existing shape refresh and incoming links are useful but are not a value watchpoint. This is substantially broader than the guarded first consumer.

Suggested proof gates: actual consumer/counters; changes via assignment, defineProperty (value and accessor), delete/re-add, shadow/prototype change, global lexical or object rebinding and eval declaration, a mutation by an inlined/unknown callback after a prior read, C API and builtins, GC with shape and object address reuse, same compiled function in different realms, and recovery after a completed terminal store. Distinguish control-path direct validation from a claim that watcher invalidation works. Record machine instructions and paired timing only after semantic results pass.
