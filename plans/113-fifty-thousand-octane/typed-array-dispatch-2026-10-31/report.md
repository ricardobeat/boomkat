# Threaded typed-array numeric access

A fresh three-second Mandreel sample of the current `95fbeb07` release build recorded typed-read handler and numeric-load helper frames, plus typed-write handler frames; it was taken over 12 repetitions of the original mini workload and is attribution, not a timing. The bytecode of its hot `sortMaxDown` function repeatedly reads `heap32` and `heapU16` through GETGLOBAL and GETPROP. The control ARM64 `th_get_typed_element` saves five register pairs and calls `ta_load_number`. Inlining that existing helper removes the call and the entire handler frame. The control integer-store handler saves three register pairs and calls `ta_store_int`. A version that simply inlines `ta_store_int` keeps a scalar fallback call and grows the frame: nine paired Mandreel medians regress 550→573 ms (+4.18%), so it was rejected.

The final integer-store path bounds the class to integer typed arrays before the inlined store; Float16/32/64 use the existing out-of-line scalar conversion and tail dispatch. BigInt classes and invalid, detached, resizable, out-of-bounds, or nonnumeric cases retain their existing fallback. A NaN-boxed fastint is at most 48 bits and converts exactly to double. The alternative value representation can store wider fastints, so those outside the 48-bit range fall back to the switch. The resulting ARM64 integer-store handler is frameless and contains no helper call; the read and write disassemblies are retained.

Read inline alone: five mini pairs gave Mandreel 554→549 ms; a separate nine-pair reverse-order confirmation gave 554→549 (-0.90%). Reusing the decoded element shift and class saved a couple of static instructions but measured 549→548 ms in nine pairs and was not retained. Splitting the float fallback from the inlined integer store gave a further 550→545 ms (-0.91%) over the read-only build in nine pairs. Five alternating paired minis against the original release medians: code-load 146→146 ms, zlib 3726→3722, Mandreel 554→544 (-1.81%), TypeScript 1228→1228, Crypto 164→164, Gameboy 276→275, DeltaBlue 89→88. The direct indexed numeric path is checked against construction through the separate scalar path for all numeric element classes, including Float16, clamped bytes, 48-bit signed limits, -0, NaN and infinities. The fixture also checks object coercion, a detached buffer, resizable length and BigInt rejection.
